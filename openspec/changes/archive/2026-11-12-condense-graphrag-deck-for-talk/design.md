# Design

## Context

動機見 proposal.md；要求見 `specs/talk-ready-slides/spec.md`。以下是影響做法的現況：

- **簡報建置**：簡報由 scratchpad 的 python-pptx 建置腳本產生，每頁是一段以 `# ---------- Slide …` 標記的程式區塊。腳本已內建兩項修正：整數 EMU 座標、圖表軸 ID 改為正整數。
- **目前頁面**（27 頁）：

  | 頁 | 內容 |
  |---|---|
  | 1 | 封面 |
  | 2 | 目錄 |
  | 3 | 問題 |
  | 4 | 核心想法 |
  | 5 | Fig. 1 管線 |
  | 6 | workflow 總覽 |
  | 7–18 | 方法細節 1–12 |
  | 19–20 | 評測設計 |
  | 21–23 | 結果 |
  | 24 | 限制 |
  | 25 | 總結 |
  | 26–27 | 備用頁 |

- **原文依據**：`RAG/2024_GraphRAG/paper.pdf`。實作時以 PyMuPDF 抽出全文作為比對基準，不把抽出的全文存進 repo。
- **既有規格限制**：
  - 可見文字不得含 § 與附錄編號，講者備註可以；
  - 程式碼識別字只能出現在 kicker 標籤與 workflow 總覽頁；
  - 「社群報告」只能出現在描述 JSON 格式的頁面；
  - 論文有對應的 workflow 都要有專頁（可以是備用頁）；
  - 須通過 Open XML SDK 驗證（0 錯誤）。

## Goals / Non-Goals

**Goals:**
- 正文 12 頁可在 15 分鐘內講完：10 個內容頁，每頁約 1–1.5 分鐘。
- 每頁只讀標題就知道結論；細節全部在備忘稿，且每個數字都有原文出處。
- 舊頁面的圖表與原文節錄都還找得到：在正文、在備用頁，或在備忘稿中。

**Non-Goals:**
- 不新增原文以外的內容、圖表或資料。
- 不改圖片裁切、不重繪原文圖。
- 不改 `code_notes_zh-TW.md` 與 `GLOSSARY.md`。

**各頁的取捨**
- 每頁條列最多 3 點；右側重點欄的大數字也算在 3 點之內。
- 第 4 頁的 workflow 對照、第 5 頁的合併規則卡片、第 8 頁的 map 呼叫表，都從正文移出：要點寫進備忘稿，原頁保留在備用頁。
- 方法頁的 kicker 保留 workflow 標籤，依既有規格：
  - 第 5 頁：`extract_graph`；
  - 第 6 頁：`create_communities`；
  - 第 7 頁：`create_community_reports`；
  - 第 8 頁：`global_search`。

**不採用**：每個 workflow 在正文各留一頁。那樣正文會超過 12 頁，而且細節頁不屬於 15 分鐘報告的主線。

### D3 備忘稿格式（正文內容頁 3–12）

```
【重點】一句話，可在 3 秒內講完
【講稿】約 150–250 字，口語、可直接照念，約 1–1.5 分鐘
【技術細節】條列，每點附出處（§x.x、Fig. x、Table x、附錄 X、Algorithm 1）
【可能追問】1–3 個問題與簡答；答案也只能引用原文，或指向備用頁頁碼
```

- 被移出或合併的內容，依 D1 的「來源」欄寫進對應頁的【技術細節】。例如新 5 頁包括：
  - chunk 600／100 tokens，600 與 2400 的實體參照數約兩倍（附錄 A.2）；
  - E.1 的 tuple 格式；
  - gleaning 使用 logit bias 100，以及「MANY entities were missed」提示；
  - claim 的定義；
  - 實體以精確字串比對合併、邊權重為重複次數、relationship strength 與邊權重的區別；
  - 建圖規模 8,564／20,691、15,754／19,520（§5.1）。
- 舊備忘稿中已標示的「報告者補充」與「推算」內容照原樣保留標示，例如 Leiden 背景與 map 呼叫推算。
- 封面、目錄與備用頁的備忘稿維持現狀（目錄頁更新頁碼說明），不套用四段格式。

### D4 原文溯源驗證（實作完成後執行）

1. 以 PyMuPDF 從 `paper.pdf` 抽出全文，正規化空白與連字號斷行。
2. 從第 3–12 頁的備忘稿抽出所有數字（含小數、千分位、百分比、範圍）。逐一檢查：
   - 是否出現在原文全文中；
   - 或所在句子含「推算」；
   - 或是章節、圖、表、頁碼等編號。

   列出不符合者，人工判讀後修正，直到清單為空。
3. 檢查第 3–12 頁的備忘稿都含四段標記，且【技術細節】每一點都有出處標記。

**不採用**：只靠人工閱讀核對。數字太多，容易漏掉。

### D5 版面與驗證

- 標題一行內完成（27pt）；超過一行就縮短，不縮字級。
- 驗證項目：
  - LibreOffice 渲染逐頁檢查；
  - `audit_pptx_quality.py`：high = 0、medium = 0；
  - Open XML SDK 驗證 0 錯誤；
  - 整數 EMU 檢查通過；
  - 可見文字中 § 與附錄為 0 筆；
  - 「開源實作」「預設值」「code_notes」為 0 筆；
  - 目錄頁碼一致；
  - 6 個論文有對應的 workflow 都出現在 kicker（含備用頁）。

## Risks / Trade-offs

- **[風險] 備忘稿變長，在 PowerPoint 簡報者檢視中需要捲動** → 【重點】放在最前面，講者只看第一行也能接上；講稿控制在約 250 字以內。
- **[風險] 合併後的標題太長而換行** → 以「結論 + 關鍵數字」為原則改寫，渲染時逐頁確認。
- **[取捨] 新 5 頁把 6 個舊方法頁濃縮成一頁** → 聽眾在正文只看到建圖主線；chunk、gleaning、claim、degree 的細節留在備忘稿與備用頁 14–18，追問時可直接翻到。
- **[風險] 頁碼大幅變動，QA 報告與圖片出處清單過時** → 依 D1 與 D2 的對照表逐項更新圖片頁碼：
  - Fig. 1：第 4 頁；
  - Fig. 4：第 6 頁；
  - Fig. 2：第 10 頁；
  - Fig. 3：第 16 頁（備用頁）。
